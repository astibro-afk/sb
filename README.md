# SB — система службы безопасности

Серверная часть SB работает на PHP и MySQL. Веб-сайт и будущие мобильные клиенты используют общую серверную бизнес-логику и базу данных.

## Основные разделы

- ежедневные отчёты и архив отчётов;
- пользователи и роли `admin`, `moderator`, `user`;
- объекты и закрепление сотрудников;
- задачи, общие назначения, комментарии, статусы и архив;
- уведомления и история действий;
- база документов с разграничением доступа по торговым объектам.

## Конфигурация и секреты

Рабочие параметры базы данных хранятся только в `config.local.php` на сервере.

- `config.php` — безопасный загрузчик локальной конфигурации.
- `config.local.php.example` — шаблон без реальных паролей.
- `config.local.php` запрещён в Git через `.gitignore`.
- FTP workflow исключает `config.php` и `config.local.php`: после первоначальной настройки они не перезаписываются обычным деплоем.

**Никогда не добавляйте реальные пароли, токены или другие секреты в GitHub, задачи, комментарии или переписку.**

## Однократный переход на локальную конфигурацию действующего сайта

Выполните этот переход вручную в панели/FTP хостинга. До завершения сайт продолжает использовать уже установленный серверный `config.php`.

1. Сделайте резервную копию файлов сайта и базы данных. Сохраните текущий серверный `config.php` только у себя — не загружайте его в GitHub и не отправляйте в чаты.
2. На сервере создайте `config.local.php` по шаблону `config.local.php.example`. Перенесите в него текущие параметры подключения к базе данных и сохраните файл в той же папке, что и `config.php`.
3. Убедитесь, что `config.local.php` загружен и содержит корректные параметры. Затем замените серверный `config.php` безопасным загрузчиком из репозитория.
4. Проверьте вход в SB, загрузку задач, уведомлений и отчётов.
5. После перехода смените пароль пользователя MySQL в панели хостинга и сразу обновите `db_pass` в серверном `config.local.php`. Повторно проверьте сайт. Если хостинг позволяет, используйте отдельного пользователя БД с минимально необходимыми правами.
6. Замените ранее опубликованный токен первоначальной настройки новым случайным значением либо оставьте `setup_token` пустым, если первоначальная настройка больше не нужна. Не храните установочные скрипты на сервере после завершения настройки.
7. Не добавляйте `config.local.php` в Git даже временно.

**Важно:** в истории публичного Git-репозитория ранее находились значения конфигурации. Удаление их из текущего файла не делает старые значения безопасными. Обязательно смените пароль БД и любые опубликованные токены; именно отзыв/ротация делает прежние значения непригодными.

## Деплой

GitHub Actions устанавливает зафиксированные Composer-зависимости, проверяет синтаксис PHP и JavaScript, затем FTP-деплой обновляет файлы сайта вместе с собранным `vendor/`. На pull request FTP-загрузка пропускается. Workflow намеренно не загружает `config.php` и `config.local.php`. Серверная конфигурация управляется отдельно, чтобы обычное обновление сайта не перезаписывало локальные секреты.

## Требования

- PHP с PDO MySQL;
- MySQL;
- HTTPS;
- API `api.php` на том же hostname, что и сайт: фронтенд использует относительные запросы к API.

Для первоначального развёртывания новой базы используйте `install.sql` и `install_auth.sql` согласно схеме проекта. Не выполняйте установочные SQL-файлы повторно на рабочей базе без предварительной проверки их содержимого и резервной копии.

## Самостоятельная регистрация пользователей

- Администратор и модератор могут создавать учётные записи через `add-user.php`.
- Модератор может назначать пользователей только на объекты в своей зоне ответственности.
- Новая учётная запись активируется по одноразовой ссылке сроком на 48 часов.
- Сотрудник самостоятельно задаёт пароль на странице `activate.php`.


## Web Push

Web Push подключается только после явного согласия сотрудника в браузере.

- Сотрудник может подключить или отключить устройство на странице `push.php`.
- Администратор видит активные устройства и может отозвать подписку.
- Для помощи сотруднику администратор создаёт персональную QR-ссылку на 15 минут. Она одноразовая и привязана к выбранной учётной записи; разрешение браузера сотрудник всё равно выдаёт лично.
- Подписки и VAPID-ключи хранятся в MySQL. Приватный VAPID-ключ не передаётся браузеру.
- Новые события сначала попадают в transactional outbox вместе с записью обычного уведомления. Отправка выполняется отдельно после завершения API-операции.
- Библиотека `minishlink/web-push` и её зависимости фиксируются в `composer.lock`; `vendor/` собирается в GitHub Actions и не хранится в Git.

### Ограничение бесплатного InfinityFree

На бесплатном тарифе нет cron/background jobs, а автоматические входящие запросы извне к сайту ограничиваются защитой хостинга. Поэтому отправка и повторные попытки выполняются при API-запросах к сайту. Если сайт полностью не используется, фоновой обработки очереди нет. Для гарантированных периодических повторов потребуется хостинг с cron либо отдельная инфраструктура очереди.

Перед включением на рабочем сайте нужно отдельно проверить регистрацию root Service Worker, реальную доставку на тестовое устройство и QR-подключение на телефоне. CI-проверка сама по себе не подтверждает доставку push на production.


## База документов

Раздел «База документов» хранит инструкции, регламенты, приказы, памятки, формы и другие рабочие материалы службы безопасности.

- Общие документы доступны всем авторизованным сотрудникам.
- Документы, привязанные к торговому объекту, доступны только пользователям с доступом к этому объекту.
- Администратор может загружать документы для всех или выбранного объекта и удалять любые документы.
- Модератор может размещать документы только в своей зоне ответственности и удалять загруженные им документы в этой зоне.
- Сотрудники могут искать, фильтровать и скачивать доступные им документы.
- Файлы хранятся в каталоге documents-storage; прямой доступ к каталогу закрыт правилами .htaccess. Скачивание выполняется через авторизованный API endpoint.
- Максимальный размер файла — 20 МБ. Разрешены PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, ODT/ODS/ODP, TXT/CSV, RTF, JPG и PNG.
