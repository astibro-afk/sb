# Ежедневный отчет СБ — серверное хранение

## Что изменено

- Поля формы и динамические строки сохраняются в MySQL через PHP API.
- Черновик формы изолирован по PHP-сессии браузера: сотрудники не перезаписывают друг другу незавершённые формы. Чтобы продолжить черновик на другом устройстве, потребуется отдельная персональная учётная запись/синхронизация черновиков.
- Списки объектов и сотрудников общие для сотрудников.
- Архив хранится отдельными серверными записями. При повторном сохранении отчёта сохраняется история версий; обновление одного отчёта не заменяет архив целиком.
- Архив и списки загружаются с сервера на любом устройстве после входа.
- Старые данные из localStorage этого браузера однократно переносятся на сервер, если соответствующего набора данных там ещё нет. После успешного переноса старые локальные ключи удаляются.
- Word и Excel по-прежнему формируются и скачиваются на компьютер. Выбранная папка для Word — только место выгрузки файлов, а не хранилище данных отчётов.
- Старый импорт JSON-архива из папки можно использовать для переноса ранее созданных файлов.

## Установка

1. Сделайте резервную копию текущего сайта.
2. В панели хостинга создайте базу данных MySQL и пользователя с правами на эту базу.
3. В `config.php` уже внесены переданные вами значения `db_host`, `db_name`, `db_user`. Проверьте, что имя базы указано полностью: если вместо `XXX` вы прислали сокращение, замените его на точное имя из панели InfinityFree.
4. Заполните `db_pass` паролем MySQL, а `app_password` замените на отдельный длинный уникальный пароль входа сотрудников. Не используйте один и тот же пароль для этих двух полей.
5. Загрузите `index.html`, `api.php` и `config.php` в ту же папку сайта, где сейчас находится главная страница. Если в папке уже есть `.htaccess`, не перезаписывайте его: сохраните резервную копию и добавьте в существующий файл правила защиты из `.htaccess` из этого пакета.
6. В phpMyAdmin выберите созданную базу и выполните `install.sql`. API также пытается создать таблицы автоматически, но лучше создать их заранее.
7. Откройте сайт по HTTPS. При первом входе браузер запросит общий пароль.
8. Проверьте на двух разных устройствах: сохраните тестовый отчёт на первом и откройте архив на втором.

## Важные замечания

- `api.php` должен находиться на том же домене, что и сайт: запросы выполняются к относительному адресу `api.php`. Для сайтов на InfinityFree в справке хостинга указано, что PHP API, вызываемый JavaScript-кодом сайта на том же hostname, поддерживается; API на отдельном поддомене может блокироваться.
- Черновик и динамические строки сохраняются в рамках сессии конкретного браузера. Архив и списки являются общими.
- В этой версии используется один общий пароль входа. Для персональных учётных записей, разграничения прав и журнала действий потребуется отдельный модуль пользователей.
- Серверные данные имеют приоритет над локальными копиями браузера. Локальные данные переносятся только для отсутствующих наборов.
- Автоматическая миграция видит старые данные только того браузера, в котором открыта новая версия. Для переноса архива с другого компьютера используйте существующий импорт JSON из папки.
- Перед рабочим запуском проверьте, что на тарифе включены PHP PDO MySQL и HTTPS.


## Самостоятельная регистрация пользователей

- Администратор и модератор могут создавать обычные учётные записи через `add-user.php`.
- Модератор может назначать пользователей только на свой торговый объект; объект берётся из его профиля.
- При создании пользователь остаётся неактивным. Система формирует одноразовую ссылку активации сроком на 48 часов.
- Модератор передаёт ссылку сотруднику вручную (например, через Telegram или WhatsApp).
- Сотрудник открывает `activate.php` и самостоятельно задаёт пароль от 8 символов. После успешной активации ссылка становится недействительной.
- Файлы `api.php`, `add-user.php` и `activate.php` должны быть загружены в одну папку на PHP-хостинге вместе с `config.php`. GitHub Pages не исполняет PHP.

**Безопасность:** если репозиторий публичный, нельзя хранить в нём рабочие пароли MySQL и токены настройки. Немедленно смените пароль MySQL и токен первоначальной настройки в панели хостинга, затем вынесите секреты из публичного репозитория в отдельный серверный конфигурационный файл, не публикуемый в Git.
